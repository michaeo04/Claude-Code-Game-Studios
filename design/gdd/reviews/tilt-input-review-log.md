# Review Log: tilt-input.md

## Review — 2026-09-21 — Verdict: MAJOR REVISION NEEDED
Scope signal: L (XL if the two named ADRs and the device spike are counted in the same work package)
Specialists: game-designer, systems-designer, qa-lead, godot-specialist; creative-director (senior)
Blocking items: 8 | Recommended: 9
Summary: The GDD was structurally complete (8/8 sections plus Visual/Audio, UI and Open Questions) and its core math checked out (F1, F3, F4 and every oracle re-computed). The review found that one of its three core mechanisms, neutral anchoring, produced a wrong neutral on the path the core audience uses most: the capture window before a restart always fell inside the frozen Hit phase (at the minimum lock it included the death frame), and the flat ±20 clamp turned a 35 deg rest pose into a permanent 0.574 steer bias. The sampling substrate also did not exist as described (`get_gravity()` has no timestamp, so the ring buffer held repeated frame reads), a stale sensor vector survives backgrounding on Android, a sensor dropout left the player with a dead control while the run continued (contradicting the GDD's own Pillar 2 claim), and no AC caught a wrong sign. Several ACs could not pass through a validated config (AC-4, 7, 10, 33, 43), and the "play anywhere" promise was wider than the roll formula supports (side-lying folds in `asin`).
Prior verdict resolved: First review

### Resolution (2026-09-21, same session)
All 8 blocking items were addressed in one revision pass. Decisions taken by the user (all four recommended options):
- Neutral policy: capture only at Menu-to-Play and at `run_resumed`; inherit the previous neutral on a restart from Hit or Paused; replace the flat clamp with a headroom clamp `L_eff = clamp(70 - FS_eff, 0, NEUTRAL_LIMIT)` and cap `FS_eff` at 50. The coupling to `RESTART_LOCK` is gone; the binding constraint is now the shortest resume countdown.
- Sensor loss: after a short hold, Tilt Input's adapter requests `pause_requested(sensor_lost)` (new Run State pause source); decay, limit and the Dropout state are deleted; Play and Resume are gated on `valid`.
- Scope cut: F5 became a design-time note, `UNITS_SUSPECTED`, `BAD_DT`, `TAU_ABOVE_CAP` and the mid-ladder capture were removed, log codes 9 to 6, states 5 to 3 (desktop keys became an input source). Oracle-exact ACs kept for the pure math and for capture and state logic; device-dependent items became spike exit criteria with provisional thresholds.
- "Play anywhere" scoped to seated, standing, reclined and steady-vehicle postures; side-lying and lying flat are unsupported until the F1 rework (Open Question 6).
Decisions taken from the review without a separate question: `dt` from the injected clock instead of a `real_dt` argument; the node handles `NOTIFICATION_APPLICATION_PAUSED` and `_RESUMED` (buffer cleared, settle window); `sensors_enabled` read from `ProjectSettings`; portrait named as `display/window/handheld/orientation` = 1 with no axis remap (verified in the 4.7.2 source); `get_gravity()` named as the working source and the 11.8 deg figure moved to the raw accelerometer; a sign-catching AC (AC-40, deferred) and a project-settings lint (AC-37); config validation order defined; `availability_changed` fires exactly when `valid` changes value.
Propagated the same day (approved by the user): Run State GDD (`sensor_lost` source, rule 14 and Tilt Input rows, pause screen message and gating, AC-29), the entity registry (`restart_lock` reference dropped, `dt_max` and `resume_countdown` comments), and the systems index (row 3 status In Review).
Deferred: the touch-steering fallback (Open Question 19, decide before MVP lock), moving `CURVE_EXP` to Ball Movement (Open Question 20), the F1 rework (Open Question 6), the on-device spike (Open Question 2), the two ADRs (sensor source, game loop) and GUT versus gdUnit4 (Open Question 16).
Status after revision: pending re-review in a fresh session (`/design-review design/gdd/tilt-input.md`).

### Resolution (2026-09-21, same session)
User decisions: (1) gate Play, Resume and Restart on `valid`, and swallow the tap-anywhere restart in Hit with a "sensor not ready" cue; Acquiring is worded "reconnecting" and Unavailable "no motion sensor"; (2) `FALLBACK` is entered automatically only when no sensor was ever live (`sensor_ever_live`); a mid-session loss stays Unavailable with a Menu path; (3) a run played with `FALLBACK` is flagged through `input_source` (Scoring decides how, Open Question 27); (4) re-anchor with `phi_stop` and a threshold in degrees.
Applied without a separate question: the pause check moved to the adapter's per-frame `flush()` between `tilt.poll()` and Run State's tick; entering `FALLBACK` clears pending and stale and capture events are no-ops there; `TiltRunAdapter` is a `RefCounted` and AC-39a-e are BLOCKING Tilt Input tests; the re-anchor window is clamped to samples taken after the run stopped and compares the clamped median; a capture event while pending restarts the accumulator; the release-build configuration-error Unavailable ignores every event; AC-16 rewritten (16a-k), AC-17, 21, 24, 33, 44, 46, 47 split, AC-43b, AC-48, AC-49 added, AC-37d parses INI and 37f added; gate policy fixed ([L] blocking, owners for AC-41 and AC-28 [I], V-1 signed by qa-lead and technical-director); V-3 and V-2 statistics corrected, V-9 added; portrait enum value 1 and lifecycle notification delivery marked verified (4.7.2 source).

Adjudicated by the creative-director: `phi_stop` discriminator plus post-stop window (not restrict-to-Paused, which would reverse the user's earlier decision); degree threshold (game-designer) over a `FS_eff` fraction (systems-designer), with the cap above added by the main session; last round's gate narrowing upheld for AC-27 and AC-40, with the adapter tests moved in scope as a correction.
