# Technical Requirements Baseline: Presentation and UI (juice-feedback, environment-theming, hud, menus-screen-flow)

Date: 2026-10-02

TECHNICAL REQUIREMENTS BASELINE: juice-feedback, environment-theming, hud, menus-screen-flow (plus the three UX specs). I read all seven files in full. I did not open docs/engine-reference. Engine property names below are my mapping from the GDD wording, and the Godot-version tags are from the brief. Verify both before ADRs.

===== 1. JUICE-FEEDBACK =====

It takes injected read-only doubles for Near-Miss, Run State, Scoring, Obstacle lookup, Camera, Platform Services, Settings and Tube Track, plus a log_sink. It has push handlers on_near_miss_detected, on_run_ended, on_run_abandoned, on_run_reset, on_personal_best_updated and a tick(dt_eff) | GDScript RefCounted; mirrors BallCore/CameraCore | Core Rules 1,13; AC Targets

TR-juice-feedback-004 | Core | Two independent tracks. Hazard-reaction: Idle/NearMiss/Hit, where a hit cuts a near-miss at once and a near-miss during Hit is dropped. Milestone: Off/PersonalBestOverlay. `run_reset` forces Idle/Off unconditionally | NEAR_MISS_WINDOW 0.08 s | States, Rules 6-8

TR-juice-feedback-013b | Timing | The flash throttle applies only to the ring flash pop. Rim, whoosh, haptic and FOV punch always fire. ARCHITECTURE FACTS (juice-feedback)
- Modules: JuiceCore (RefCounted), JuiceMath (static), JuiceConfig (Resource). A view and presentation layer (shader term, GPUParticles3D, overlay, audio players) is implied but not named.
- OWNS: both presentation tracks, the run-end latch, the F2 cooldown, the shared flash ledger, the hit/near-miss/PB visuals and audio, and `hitstop_actual` (injected into Run State).
- EXPOSES: no signals. It may offer read-only track state to HUD (provisional). Nothing is pushed to HUD.
- CONSUMES: near_miss_detected(hazard_id, run_id), run_ended(run_id, hazard_id, run_time_ms), run_abandoned(run_id, run_time_ms), run_reset, personal_best_updated(final_score), the Obstacle hazard lookup (id, footprint, type), reduced_motion_enabled, CAMERA_FOV, Tube Track P(theta,s,h), s, L, n_seams and f_seam, and the haptic schema.
- Engine classes: Camera3D (through Camera), GPUParticles3D, ShaderMaterial/spatial shader, CanvasLayer overlay, AudioStreamPlayer (my inference).
- Init: composition-root preflight runs validate_flash_budget and validate_hitstop after Tube Track and Run State validation, then injects hitstop_actual. Per-tick: tick(dt_eff) after upstream events. The `run_ended` handler is registered FIRST.

===== 2. ENVIRONMENT-THEMING =====
TR-environment-theming-001 | Data | `EnvConfig` is a Resource holding every MapConfig field it owns (seam_pattern_id, fog_mode, fog_depth_begin, fog_end_distance, fog_depth_curve, fog_density, fog_color, readable_distance, tube_color, sky_top_color, sky_bottom_color, prop_set_id) plus the knobs. `validated(log_sink)` returns a clamped copy | Map 1: begin 44, F 84, curve 1.0, density 1.0, fog_color Haze Low #E6EDF5 | Rules 1,13
TR-environment-theming-002 | Core | `EnvMath` is a static class: factor, luminance blend, contrast, an F_read bisection search, F2 fog_end_distance(speed) and F3 L_ball_adjusted. All are parametric in MapConfig and never hardcoded to Map 1 | F_read 46.221 u at 1e-3; L_ball_adjusted 0.042143 at 1e-6 | Rule 13, F1-F3
TR-environment-theming-003 | Core | `EnvCore` is a RefCounted with no engine calls. It takes injected speed and colorblind_safe_enabled doubles and a log_sink, and holds the MapConfig and the last L_ball_adjusted. It is deterministic | same inputs give bit-identical outputs | Rules 12-13
TR-environment-theming-004 | Rendering | Fog uses a depth ramp with factor = smoothstep(begin, end, d)^curve * density. Density must be 1.0, because exponential mode never reaches 100%. d is radial from the camera eye | Environment fog: FOG_MODE_DEPTH, fog_depth_begin/end/curve, fog_density (4.3+ API, M). Name mapping to GDD fields is unverified | Rules 3-4, F1
TR-environment-theming-005 | Core | Map load computes F_read from the 4:1 contrast crossing. It rejects with MAP_VISIBILITY_UNSAFE if F_read < T_VIS_MIN*v_max + d_cam, evaluating the speed-pulled F at v_max. A bad range gives FOG_RANGE_INVALID | floor 45.34 (d_cam 7.84) or 45.5 (legacy); T_VIS_MIN 1.5 s | Rules 3,4,11
TR-environment-theming-006 | Rendering | Speed-driven fog pull moves only fog_depth_end (written each frame while Running). u = clamp((speed-10)/15, 0, 1) and F = F_base - FOG_PULL_MAX*u. fog_depth_begin is never pulled, because F_read is about 17x more sensitive to it. F stays above F_read | FOG_PULL_MAX 4 (0-8, ceiling about 13.0); F_read at v_max 46.00 | Rule 5, F2
TR-environment-theming-007 | Rendering | A world chroma multiplier of 0.88 at v_max applies to tube, sky and prop materials only. It is a separate parameter from any hazard/ball/pickup parameter, never a shared uniform gated by an object flag | shader global or per-material uniform; 4.7 shader preprocessor restrictions (H) | Rule 5, V/A
TR-environment-theming-008 | Rendering | The Menu state evaluates no speed formula and shows resting fog values. The preview hazard holds a fixed screen position independent of s_idle | AC-12 | Rule 6, V/A table
TR-environment-theming-009 | Rendering | colorblind_safe_enabled applies L_ball_adjusted to the ball material itself. It is read from the getter at construction/map load AND on setting_changed, in any phase, with no wait for run_reset. Only the lightness axis changes | R_target 1.4, margin_ember 0.01; luminance 0.083 to 0.0421 | Rule 9, F3, AC-19,23,24,25
TR-environment-theming-010 | Core | The F3 clamp is L_ball_adjusted = max(min(L_base, L_target), L_floor). It is bit-identical to base when the toggle is off, and it re-derives from the map's own L_hazard and L_ember | AC-8..11 | F3
TR-environment-theming-011 | Core | The only ball-related output is the single l_ball_adjusted value. Environment makes no request to any other system, and Ball Movement has no consumer | banned tokens ball_scale, ball_tint, ball_speed, set_ball_ | Rules 7,12, AC-13
TR-environment-theming-012 | Rendering | The Double Gate plinth is environment-owned geometry. Height is 0.15D, the span is the gate arc plus a 0.5D margin each end, the edge is filleted, chroma is at most 0.05, and it never uses the Signal Red or Ember hex. It is subject to the 0.88 chroma shift | 0.12 u at D 0.8 | Rule 10, V/A
TR-environment-theming-013 | Rendering | Background props are MultiMesh-instanced, 3-6 meshes. A palette-swap map is retinted material parameters only, with zero new draw calls. New geometry needs its own budget | MultiMeshInstance3D (L); total at most 150 draw calls | V/A footprint
TR-environment-theming-014 | Rendering | The tube, sky and prop materials use a sky gradient of 2 stops. Sky hue is constant across states. Mood is carried by fog, chroma and light key only | Sky shader or ProceduralSkyMaterial (inference); WorldEnvironment (L) | V/A table
TR-environment-theming-015 | Rendering | Glow and tonemap behaviour on Forward+ (glow before tonemapping since 4.6) must not disturb the contrast numbers. The F1 derivation assumes Forward+ fog. The Mobile renderer is unverified | WorldEnvironment glow (H, 4.6) | Open Question 5, AC-22
TR-environment-theming-016 | Timing | Per-frame order is Ball speed read, then F2 evaluation, then the fog write and chroma uniform write. The toggle is event-driven and not per-frame | once per frame | Interactions, States
TR-environment-theming-017 | Data | Persistent state: none. colorblind_safe_enabled is persisted by Settings and only read here. EnvCore holds the last L_ball_adjusted in memory | none | Rule 13
TR-environment-theming-018 | Testing | Tests live in tests/unit/environment_theming/ as environment_theming_[feature]_test.gd. make_env_fixture returns Map 1 data. Bisection oracles are computed from the formula. A lint bans request_, Input., Engine., Time., OS., DisplayServer., get_tree, _process and randi in EnvMath/Core/Config | AC-1..25 | AC section
TR-environment-theming-019 | Testing | Deferred checks: the integration driver with a real BallCore, and on-device Mobile-renderer contrast sampling. ENV-1 is a mood screenshot, ADVISORY | AC-21, 22, ENV-1 | AC section

ARCHITECTURE FACTS (environment-theming)
- Modules: EnvMath (static), EnvCore (RefCounted), EnvConfig (Resource). A view layer that writes the Environment/materials is implied but unnamed.
- OWNS: the tube, sky and prop palette and materials, the fog fields, derived F_read, the ball material's luminance adjustment, the plinth, and the Menu preview hazard's screen anchor.
- EXPOSES: MapConfig fog and colour fields (published at map load to Tube Track), and l_ball_adjusted. It exposes no signals.
- CONSUMES: Ball Movement `speed` (every frame), Settings colorblind_safe_enabled getter plus the setting_changed signal, Tube Track R and segment data, and the art-bible fixed hazard luminances (read-only).
- Engine classes: WorldEnvironment/Environment (fog, glow), a sky shader, shader global parameters (my inference), MultiMeshInstance3D, StandardMaterial3D/ShaderMaterial.
- Init: map load runs EnvConfig.validated and the F_read gate, then builds the ball material and applies L_ball_adjusted from the getter before the first Menu frame. Per-tick: runs after Ball Movement updates speed, before render.

ARCHITECTURE FACTS (hud)
- Modules: HudCore (RefCounted), and a Control view layer (tap catcher, pause and Menu buttons, pills, banner tween). The view layer is not named and is `/ux-design` scope.
- OWNS: HUD display state, the was-Live latch, the banner, the NEW BEST state, the sensor cues, and the Hit-phase Menu button.

ARCHITECTURE FACTS (menus-screen-flow)
- Modules: MenuCore (RefCounted), MenuConfig (Resource), and a Control view layer for Menu, Paused, Settings, confirm-quit, failure and the Ink cover. The view layer is not named.
- OWNS: which top-level screen is active, the overlay flags settings_open and confirm_quit_open, the transition_covering flag, and quit() routing.
- EXPOSES: a display-state snapshot, transition_covering, and the 7 outbound calls.
- CONSUMES: Run State phase_changed and run_paused(source). From Tilt Input it pulls valid, state and input_source. From Scoring it pulls personal_best (re-pulled on Menu entry). From Settings it uses 5 getters and set_value. From Platform Services it takes back_pressed, quit and haptic, plus the safe area.
- Engine classes: CanvasLayer, Control/Button/ScrollContainer/Panel, Tween, InputEventScreenTouch, SceneTree.quit (via Platform Services), DisplayServer.
- Init: MenuCore is built with injected seams. Per-tick: tick(dt) pulls the Tilt seam and Boot time. It runs independently of HUD, with no data flow between them.

===== CONFLICTS OR GAPS =====
Juice
1. The hitstop mechanism is unspecified. It could be Engine.time_scale or SceneTree.paused. Run State's RESTART_LOCK and the flash ledger must keep running in real time through the freeze. It also does not say how the ball is frozen while shards play.
2. The grey-out mechanism is undefined. A hazard-exempt chroma multiply needs a per-hazard parameter. It also does not say how it composes with Environment's 0.88 world chroma uniform, so a single owner for the chroma uniform is needed.
3. The total durations of the hit presentation, shard lifetime and PB bloom/sweep are not given. Track return to Idle (AC-10) is therefore untestable. The flash "held under threshold" level is also not given.
4. The JuiceCore presentation-sink interface and the "rendering/audio stub" allowlist are not defined. There are no audio asset, bus or class specs.
5. The near-miss ring is clipped from hazard footprints, but the hazard screen-area data and clipping mechanism are not specified.
6. The ball rim glow and Environment's L_ball_adjusted both modify the ball material, with no single owner or layering defined.
7. The seam-crossing detection that derives ledger timestamps from s, L and n_seams (phase offset, Menu idle) is not specified.
8. The PB cool bloom is described as an opacity overlay. If it is built with WorldEnvironment glow, the 4.6 glow-before-tonemapping change makes it unpredictable. This is not specified.
9. Tube Track's surface-anchored effect frame signature is cited but not defined here.

Environment
10. Env OQ5 says the Mobile renderer is the "likely" target, but technical-preferences.md says Forward+. The F_read derivation is only valid for Forward+. This is a direct conflict.
11. The GDD says "default exponential fog mode" must be avoided but never names FOG_MODE_DEPTH. GDD fields map to Godot properties only by inference (fog_end_distance to fog_depth_end). Sky fog (fog_sky_affect, fog_light_color, fog_aerial_perspective) is unspecified.
12. The chroma-shift mechanism (shader global versus per-material uniform) and how hazards, ball and pickups stay exempt are not defined. 4.7 preprocessor limits apply.
13. Who instantiates the ball material when Ball Movement owns the ball node is not stated. The Menu preview hazard's drawing node and its "published screen-anchor" (AC-12) are not defined. The plinth spawner is not named (Obstacle or Environment).
14. The fog behaviour at run_reset or in Hit (speed snaps to V_START) is unspecified, as is the EnvCore tick API signature.

HUD
15. press_us has no defined clock or source. InputEventScreenTouch carries no timestamp, so the view must stamp it from a clock whose domain matches Run State F3/F4 (Run State Rule 8 not read). Press-down time versus handling time is undecided.
16. Run State has not yet exposed F5 as a read accessor (hud.md OQ7). The GDD says the shorter digit is last, but ceil() makes it first.
17. Score and BEST shrink floors conflict (20 sp versus 14 sp). More than 8 digits is undefined. hud.md says "right-anchored" but the UX puts Z1 top-left.
18. The dp conversion (dpi source, stretch mode) needs an ADR, and no project.godot exists. System gesture insets are unavailable, so Z2's 40/16 dp are unverified. CanvasLayer.layer index values for HUD, Menus and the cut are not assigned.
19. The UX Menu "inactive until unlocked" state needs restart_unlocked state in HudCore, but hud.md Rule 7 does not describe it. The snapshot schema is undefined.

Menus
20. The Ink cut (UX) fades to Ink for 80-100 ms BEFORE the seam jump, yet "Z1 and Z2 appear in the same tick as the phase change". The fade cannot precede the jump unless the phase transition or start_requested is delayed. The ordering between the cover and Run State is undefined.
21. MenuCore has no seam for the "Retrying" state (Retry dimmed with pulse). The origin of elapsed Boot time (app start versus Boot entry) is not defined, nor whether it is pulled or accumulated from dt. The loader interface is provisional.
22. The tap-versus-scroll arbitration in the Settings list and the focus behaviour under 4.6 dual-focus (touch focus_mode) are not specified.
23. Touch-to-mouse emulation (emulate_mouse_from_touch) and the 4.7 input-device ID renumbering effect on InputEventScreenTouch handling are not addressed anywhere.
24. The Menus UX spec has duplicate empty Accessibility and Localization stub sections, which should be cleaned up. The Paused screen was drafted but is pending /ux-review.
