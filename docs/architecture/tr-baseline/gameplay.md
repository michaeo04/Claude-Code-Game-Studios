=== 1. OBSTACLE SYSTEM (design/gdd/obstacle-system.md) ===
TR-obstacle-system-001 | Core | Logic is split into static pure `ObstacleMath` (F1 expansion, F2 swept overlap + `arc_overlap`, F3 gap sweep-line, F4 `hidden()`, F5 spacing), `RefCounted` `ObstacleCore` and a data-driven `ObstacleConfig` Resource with `validated(log_sink)`. | RefCounted, Resource; GDScript static typing (L) | Acceptance Criteria Targets, Tuning Knobs
TR-obstacle-system-002 | Core | A hazard is `{hazard_id:int>=0, footprint_pieces:[(theta_min,theta_max,s_start,s_end)], home_segment}`. Pieces of one hazard share one id. Raw `s`-range of every piece lies inside `[i*L,(i+1)*L)`. No height dimension. | float64 math; `hazard_id` restarts at 0 per run | CR1
TR-obstacle-system-003 | Physics | The hit test is analytic (no `CollisionObject3D`/`Area3D`/`PhysicsServer3D`). It is a swept AABB: `s_hit = s_prev<=s_eff_end and s>=s_eff_start`, and `theta_hit = arc_overlap(...)` using a single `fposmod`. Bounds are expanded by `BALL_HALF_ANGLE = asin(D/(2(R+D/2)))` and `D/2`. | `fposmod` (L); `BALL_HALF_ANGLE` 0.1179 rad at defaults | CR2, F1, F2
TR-obstacle-system-004 | Timing | The test runs exactly once per published `(theta_prev,theta,s_prev,s)` pair, in the same tick domain as Ball Movement's publish. A driver node owns this guarantee. A render-frame-only callback is forbidden because of physics catch-up. | `Engine.physics_ticks_per_second`, `Engine.max_physics_steps_per_frame` (default 8) (L); `_physics_process` vs `_process` must match Ball Movement | CR2, OQ16, AC-25
TR-obstacle-system-005 | Core | Reporting is level-triggered. One `hit_reported(hazard_id:int, run_id:int)` is sent per overlapped hazard per tick, in every phase, with no phase awareness (a no-op frame degenerates to a point-in-footprint test). | signal; payload (int,int) | CR3, CR4, AC-16, AC-17, AC-18
TR-obstacle-system-006 | Core | Lifecycle follows Tube Track's signals. `segment_entered_window(i)` calls the provider once and spawns hazards. `segment_left_window(i)` releases them. `window_primed(first,last)` releases everything, then populates `[first,last]` in increasing order and restarts the `hazard_id` counter at 0. | Tube Track signals; no diffing | CR5, AC-19, AC-20, AC-21
TR-obstacle-system-007 | Core | Obstacle System emits `hazard_bound(hazard_id, footprint_pieces)` on spawn and `hazard_released(hazard_id, released_by_reset: bool)` on release. The flag is true for any `window_primed`-caused release (reset, re-prime, to-idle) and false for a `segment_left_window` recycle. No release event exists for `unload_map`. | signals (Obstacle -> Near-Miss) | CR5, Interactions, AC-40
TR-obstacle-system-008 | Core | The `run_reset(run_id)` handler only stores `run_id`. It must not clear, reseed or reset the id counter, so either order within rank 2 is safe. | Run State subscriber rank 2 (with Tube Track adapter) | CR5, AC-41
TR-obstacle-system-009 | Data | The content seam is `HazardContentProvider.hazards_for_segment(segment_index:int) -> Array[HazardSpec]`. Swapping providers needs no core change. | typed Array return (L); `@abstract` (4.5, H) optional for the interface | CR7, EC, AC-14
TR-obstacle-system-010 | Data | If `HazardSpec` is a Resource, each spawned hazard gets an owned deep copy. Plain `duplicate()` is shallow. | `Resource.duplicate(true)` / `duplicate_deep()` (4.5, H) / `CACHE_MODE_IGNORE` | CR7
TR-obstacle-system-011 | Data | Footprint bounds are unwrapped reals with `theta_min<=theta_max` and width `<2*PI`. A seam-crossing piece is authored with `theta_max>PI` or `theta_min<-PI`. Bounds are wrapped only when compared to the ball. | e.g. (2.9, 3.6) | F1, F2, AC-4
TR-obstacle-system-012 | Core | An offline preflight runs over the whole library, exhaustively (not fail-fast), in deterministic order. TR-obstacle-system-013 | Core | The live `hazards_for_segment` call may re-run the checks only as a debug-build assertion. It never rejects mid-run. | debug-only | EC "When validation runs"

ARCHITECTURE FACTS (Obstacle System)
- Modules: `ObstacleMath` (static), `ObstacleCore` (RefCounted), `ObstacleConfig` (Resource), an unnamed driver node, and the `HazardContentProvider` seam.
- OWNS exclusively: hazard instances and `hazard_id` assignment, the collision test (sole collision owner), the preflight validators, and the bind/release lifecycle.
- EXPOSES: signals `hit_reported(hazard_id, run_id)`, `hazard_bound(hazard_id, footprint_pieces)`, `hazard_released(hazard_id, released_by_reset)`. Bound footprints and `hazard_id` stay queryable by Juice for the killer-isolate effect.
- CONSUMES: Ball Movement `theta/theta_prev/s/s_prev`; Tube Track `segment_entered_window`, `segment_left_window`, `window_primed`, `delta_theta`, `L`, `wrap_angle`; Run State `run_reset(run_id)`; Camera `VISIBLE_ARC_HALF_WIDTH`; Pattern `hazards_for_segment`.
- Engine classes touched: none in core. Resource (HazardSpec) and signals only.
- Order: `run_reset` rank 2 (capture `run_id` only, shared with Tube Track adapter, after Pattern rank 1). `window_primed` fires inside `begin_run()` and populates. The per-tick test runs after Ball Movement's step.

=== 2. PATTERN & DIFFICULTY (design/gdd/pattern-difficulty.md) ===
TR-pattern-difficulty-001 | Core | Logic is split into static `PatternMath` (F1 tier, F2 opposing/spacing, F3 cost ratio, F4 bag bounds), `PatternCore` (RefCounted: provider impl, seeded RNG, bags, read history, padding), and `PatternConfig.validated(log_sink)` (library preflight). | RefCounted, Resource | Acceptance Criteria Targets
TR-pattern-difficulty-002 | Data | Chunk record: `{chunk_id, tier, segment_count 1-3, hazard_placements:[(local_segment_index, hazard_type, footprint_pieces)]}` in chunk-local coordinates. At `base`, pieces are translated by `base*L` in `s`. Whole-segment alignment is forced by Obstacle's `HOME_SEGMENT_MISMATCH`. MVP types: Wall, Spike, Double Gate, Near-Ring. | L=12; 8-chunk fixture | CR1, CR4, AC-2, AC-7
TR-pattern-difficulty-003 | Data | PatternCore is the `HazardContentProvider`: `hazards_for_segment(index)` returns empty for `index<0`, the next local segment's translated pieces mid-chunk, empty while padding, else it draws a new chunk. | `Array[HazardSpec]` | CR5, States table, AC-8
TR-pattern-difficulty-004 | Core | Tier is a pure function of `run_time`: INTRO `<TIER_INTRO_DURATION`, RAMP `<TIER_RAMP_DURATION`, FULL after, with the upper boundary inclusive. Pools are supersets (RAMP includes INTRO, FULL includes all). Tier changes lazily at the next chunk draw and never truncates a chunk. | 15 s / 90 s (=T_RAMP) | CR2, F1, AC-1, AC-3
TR-pattern-difficulty-005 | Core | Per tier, a bag is shuffled with a PRNG seeded from `run_id`, drawn without replacement, and reshuffled on empty. The reshuffled first draw must differ from the previous last draw (waived at N=1). `min_gap`=2, `max_gap`=2N-1 for N>=3, fixed 2 at N=2. | N=4/6/8 fixtures | CR3, F4, AC-4, AC-5, AC-6, AC-15, AC-31
TR-pattern-difficulty-006 | Core | The PRNG is a `RandomNumberGenerator` with an explicit `seed` set from `run_id` before the first draw, never `randomize()`. Fisher-Yates is implemented by the module itself (the shuffle must use this RNG instance). | `RandomNumberGenerator.seed` (L); `Array.shuffle()` uses the global RNG, so it must be avoided | CR3, CR11, AC-24
TR-pattern-difficulty-007 | Core | On `run_reset(run_id)` Pattern reseeds, reshuffles all three bags, discards in-progress chunk state and clears the read history. It must run first among `run_reset` subscribers. | Run State rank 1 | States table, AC-20
TR-pattern-difficulty-008 | Core | The first chunk draw of a run is restricted to grace-compliant INTRO chunks (translated `s_start>=11` at base 0). Later draws are unrestricted. `GRACE_POOL_TOO_SMALL` requires at least 2 compliant chunks. | grace 11 u; `GRACE_POOL_MIN_SIZE`=2 | CR6, AC-9, AC-9b
TR-pattern-difficulty-009 | Core | The preflight inherits Obstacle's gates. Every authored piece must pass `HIDDEN_CONTENT_FORBIDDEN` (per piece) and `EXIT_BEYOND_VISIBLE_ARC` (per `theta_solution`). | 1.0472 shipped, 1.5708 fixture | CR7, AC-10
TR-pattern-difficulty-010 | Core | Solution angles: Wall and Near-Ring have one (gap midpoint), Double Gate has two, Spike has none (exempt). Two reads are opposing if any angle pair has `abs(delta_theta)>ANGULAR_REVERSAL_THRESHOLD` (strict `>`). Opposing pairs need `s_start` distance `>=DODGE_RECOVERY_S = T_DODGE_180*v_max`. A within-chunk violation gives `DODGE_RECOVERY_VIOLATION`. | PI/2 threshold (safe PI/3-2PI/3); DODGE_RECOVERY_S=26.6 u (range 16.92-42.0) | CR8, F2, AC-11, AC-12b, AC-12c
TR-pattern-difficulty-011 | Core | Cross-chunk spacing is enforced by sequencer padding. A pruned read history holds `(s_start, theta_solution_set)` for non-Spike reads (pruned to `s_start >= frontier - DODGE_RECOVERY_S`). Every non-Spike read of a drawn chunk is checked against every history entry. `padding_segments = ceil(max_shortfall/L)` empty segments are inserted before the chunk. It never redraws, reorders or rejects. | worst case 5 segments (`ceil(1.4*3.0)`); 3 at defaults | CR9, F2c, AC-12, AC-13
TR-pattern-difficulty-012 | Core | F3 must delegate to Ball Movement's `BallMath.T` (three-branch F5a), not restate the middle branch (NaN/wrong value when `BALL_LAG_TAU<=eps/OMEGA_MAX`). | eps 0.05; AC-30 cost_ratio(PI/2)=0.492 at tau=0 | F3, AC-30
TR-pattern-difficulty-013 | Core | The pool clustering statistic `opposing_pair_fraction` is computed per tier. A value above `MAX_OPPOSING_FRACTION` logs an ADVISORY `EXCESSIVE_ANGULAR_CLUSTERING` (load still succeeds). It is 0.0 (no NaN) when fewer than 2 non-Spike chunks. | 0.6 (0.4-0.8); FULL fixture 11/21=0.524 | CR12, F5, AC-28, AC-29, AC-29b
TR-pattern-difficulty-014 | Data | Config guards: `TIER_ORDER_INVALID`, `TIER_DURATION_OUT_OF_RANGE` (intro 8-20, ramp 45-240, checked first), `ANGULAR_THRESHOLD_OUT_OF_RANGE`. `t_dodge_worst` = `T_DODGE_180` is supplied to Tube Track as a config value, never derived per chunk. | `PatternConfig.tres` | F1, CR10, AC-1b, AC-1c, AC-16
TR-pattern-difficulty-015 | Core | Determinism: the same `run_id` and the same call script give bit-identical chunk sequences. A different `run_id` changes the first draw. No side effects; Run State and Tube Track are read-only. | AC-17, AC-18 | CR11
TR-pattern-difficulty-016 | Timing | Obstacle must call `hazards_for_segment` in increasing index order, once each. PatternCore state (mid-chunk, mid-padding) depends on call order. Tier is sampled at window-entry time (ahead of the ball). | up to N_MAX=16 segments ahead | States table, F2c
TR-pattern-difficulty-017 | Timing | Per-call cost is small (bag draw plus history check against a short pruned history). No explicit budget is given. | history holds a few entries | F2c
TR-pattern-difficulty-018 | Testing | Lint bans the engine-coupling tokens except `RandomNumberGenerator` with an explicit seed (the lint must verify seed-before-first-draw). The 8-chunk fixture with INTRO={W1-W4}, RAMP=+{SP1,DG1}, FULL=+{NR1,REV2} drives the tests, plus micro-fixtures TWOHOP, TOO_CLOSE, TWIN_WALL and CLUSTERED. Files are `pattern_difficulty_[feature]_test.gd`. | GUT; AC-24 | Acceptance Criteria
TR-pattern-difficulty-019 | Testing | The statistical shuffle-fairness test is ADVISORY: chi-square over 500 `run_id`s, N=8, p>0.01. Use a fixed hardcoded seed list, not generated seeds. | AC-23, AC-9 | F4
TR-pattern-difficulty-020 | SaveLoad | No persistence. All chunk and sequence state is per-run and in-memory. | none | CR11
TR-pattern-difficulty-021 | Data | The chunk-library data format is only logically specified (the record in TR-002). The on-disk format and the `PatternConfig.tres` fields beyond the three knobs are not fixed. | gap, see CONFLICTS | CR1, Provisional assumptions

ARCHITECTURE FACTS (Pattern & Difficulty)
- Modules: `PatternMath`, `PatternCore` (is the `HazardContentProvider`), `PatternConfig`, and the chunk library (fixture today).
- OWNS exclusively: chunk definitions, tier selection, bag and PRNG state, read history and padding, the within-chunk spacing validator, and pool clustering.
- EXPOSES: `hazards_for_segment(int) -> Array[HazardSpec]` and `t_dodge_worst` (config value to Tube Track). No signals, no requests.
- CONSUMES: Run State `run_id` (from `run_reset`) and `run_time`; Tube Track `SEGMENT_LENGTH` and `SEAM_HZ_MAX`; Ball Movement `V_MAX`, `T_DODGE_180`, `OMEGA_MAX`, `BALL_LAG_TAU`, `STEER_ARC`, `speed(t)`; Obstacle F-validators and constants.
- Engine classes: `RandomNumberGenerator` (seeded), Resource.
- Order: `run_reset` rank 1 (before Tube Track `begin_run`/`window_primed`). Called by Obstacle on each `segment_entered_window` and on `window_primed` repopulation.

TR-near-miss-detection-002 | Core | Per-hazard state is `{hit_ever_true, was_in_near_zone}` keyed by `hazard_id`, created on `hazard_bound` and discarded on `hazard_released`. | Dictionary by int | CR1, States table
TR-near-miss-detection-003 | Physics | `near_zone = hit_zone expanded by NEAR_MISS_ANGLE_MARGIN = COEFF*BALL_HALF_ANGLE` and `NEAR_MISS_S_MARGIN = COEFF*D/2`. `NEAR_MISS_CANDIDATE = NEAR_ZONE and not HIT_ZONE`. TR-near-miss-detection-004 | Core | Output is edge-triggered: exactly one `near_miss_detected(hazard_id:int, run_id:int)` on the near-zone true->false edge, or on a release with `released_by_reset==false`. TR-near-miss-detection-005 | Core | A hit overrides: `hit_reported` sets `hit_ever_true`, and the hazard never emits a near-miss. Within a tick, `hit_reported` is applied before the exit-edge check, regardless of driver delivery order. | AC-11, AC-12 | CR4
TR-near-miss-detection-006 | Core | A release with `released_by_reset==true` emits nothing (reset, re-prime, to-idle, Paused to Restart/Menu). Suppression is at the source. | `hazard_released(id, bool)` | CR5, EC, AC-28
TR-near-miss-detection-007 | Core | One report per hazard, not per piece (multi-piece hazards share one state entry). | Spike 101, Double Gate 202 | CR6, AC-15
TR-near-miss-detection-008 | Data | The `near_miss_detected` payload is exactly `{hazard_id, run_id}` (strict allowlist, no closeness value). `run_id` is read from the last `run_reset` seen. | AC-16 | CR7
TR-near-miss-detection-009 | Core | Config guard: `NEAR_MISS_ANGLE_COEFF` or `NEAR_MISS_S_COEFF` <= 0 gives `NEAR_MISS_MARGIN_NONPOSITIVE`. Strict containment of the hit zone in the near zone is the invariant. | 1.0 each (0.5-1.5) | F1-NM, EC, AC-7
TR-near-miss-detection-010 | Core | Preflight `NEAR_ZONE_OVERLAP` covers the 3+ pieces sharing a critical `s0` case. It is checked on angularly adjacent neighbors, including the wraparound pair, over the whole library, using near zones. It must not fire for non-adjacent pieces. The two-piece proof is `fraction_consumed = k/GAP_MARGIN < 1`. | k<=1.5, GAP_MARGIN>=2.0 gives 0.75 | F3-NM, AC-8, AC-9, AC-10
TR-near-miss-detection-011 | Timing | The test runs every tick in every phase (stationary degenerate case). A non-finite `theta` or `s` is a no-op frame (hold last good, log one error). | AC-17 | CR8, EC
TR-near-miss-detection-012 | Timing | Along-track margin time budget is `S_MARGIN/v_max`: 16 ms at defaults, about 5 ms at the worst legal corner, so near-zone detection can be lost to a dropped frame. | 0.4 u / 25 u/s | F1-NM note, NM-1
TR-near-miss-detection-013 | Core | Same-tick `hazard_bound` plus `hazard_released` creates then tears down with no emit. A release on the same tick as a natural exit emits exactly once. | AC-18 | EC
TR-near-miss-detection-014 | Core | No side effects. Nothing is sent to Ball Movement, Obstacle or Run State. Inputs: `theta`, `theta_prev`, `s`, `s_prev`, the three Obstacle signals, `run_id`. | AC-20 | CR9
TR-near-miss-detection-015 | Core | Determinism: no randomness; bit-identical streams over a 500-tick script; no shared static state. | AC-19 | CR8
TR-near-miss-detection-016 | Testing | Lint (engine-coupling regex family, as Obstacle) plus a reuse-not-reimplement guard (no second `arc_overlap`, and a behavioral parity check against `ObstacleMath` on the AC-3..AC-6 poses). Fixtures `make_near_miss_fixture`, `make_hazard_bound_stub`, `make_core`. | AC-21, AC-22 | Acceptance Criteria
TR-near-miss-detection-017 | Testing | NM-1 on-device check, BLOCKING at first-playable: near-miss-to-hazard-passed ratio within +/-20% between early (<20 s) and late (>T_RAMP) bands, at least 30 hazards passed per band. Failure response: adjust the coefficients inside 0.5-1.5, never `GAP_MARGIN`/`GAP_MIN`. | device spike with BM-1/BM-3 | NM-1
TR-near-miss-detection-018 | SaveLoad | None. Tuning in `NearMissConfig.tres` (AC-27 advisory). | none | Tuning Knobs
TR-near-miss-detection-019 | Rendering | None owned. Juice owns the VFX/audio/haptic. A coalescing requirement is handed to Juice (two near-misses within a short window must merge into one cue). | OQ8 | Visual/Audio, OQ8

ARCHITECTURE FACTS (Scoring & Personal Best)
- Modules: `ScoreMath`, `ScoreCore`, `ScoreService` (driver node), `ScoringConfig`.
- OWNS exclusively: `current_score` and `personal_best` (in-memory) and the three latches.
- EXPOSES: `get_current_score()`, `get_personal_best()`; signals `personal_best_updated(final_score)`, `personal_best_passed(personal_best)`, `milestone_crossed(threshold)`. HUD, Juice and Menus consume; HUD declines `milestone_crossed`.
- CONSUMES: Ball Movement `s`; Run State `run_reset`, `run_ended`, `run_abandoned`; Save & Persistence `get_value`/`set_value`.
- Engine classes: Node (driver), RefCounted, Resource, `Callable`; signal connections.
- Order: `run_ended` / `run_abandoned` rank 2 (after Juice, before HUD); `run_reset` rank 5. `step()` runs after Ball Movement's step on every moving tick.

=== CONFLICTS OR GAPS ===
1. HazardSpec shape is unspecified. Only the call signature of `hazards_for_segment` is fixed (Obstacle CR7, Provisional assumptions). There is no Resource vs RefCounted vs Dictionary decision and no field list for hazard type or mapping to `footprint_pieces`.
2. The chunk-library on-disk format is unspecified (.tres vs JSON, `HazardPlacement`/`Chunk` Resource classes, where `theta_solution` is stored or derived from pieces). Only the logical record exists (Pattern CR1). The `MapConfig` field that selects a library is unnamed (Pattern OQ4).
3. The offline preflight has no named owner or entry point. Obstacle says "whatever tool or test harness drives the content pipeline" calls every index. Pattern's library is sequenced stochastically (bags, padding), so "call every segment index" has no enumeration. It is undefined whether preflight runs per chunk in isolation, per fixed sample sequences, or over worst-case adjacencies. The tools-programmer task is not ticketed (Pattern OQ8).
4. Probable cross-chunk validator hole. Padding is inserted only for opposing pairs. Non-opposing adjacent chunks are governed only by Obstacle `S_MIN_SPACING` (6.25 u) and `HAZARD_OVERLAP`, which Obstacle checks at preflight only. Fixture example: W4 (s_start 11.0) followed by W2 (next segment, 12+5.0=17.0) is 6.0 u, below 6.25. W4 followed by W1 gives 3.0 u. SP1 at s 0.0 after W4 gives 1.0 u, and effective footprints overlap in s and theta. Nothing at sequencing time prevents or detects this, so the claim that every legal chunk is safe next to every other is not backed for TOO_DENSE/HAZARD_OVERLAP/NO_SAFE_GAP across chunk boundaries.
5. Per-tick order across cores is unpinned. The subscriber-order list covers only `run_reset`/`run_ended`/`run_abandoned`. Near-Miss needs `hit_reported` applied before its same-tick exit-edge check. If NearMissCore ticks before ObstacleCore emits that tick's `hit_reported`, a near-miss could fire alongside a hit. The GDD says only the core's internal order is contracted. The relative tick order of ObstacleCore, NearMissCore, Ball Movement and ScoreService is deferred to the unwritten game-loop ADR (Run State OQ4).
6. Signals vs calls: whether `hit_reported` is a Godot signal or a direct call into Run State is not stated (Run State calls it a "request"). Who owns the Obstacle driver node, and its `process_priority` / `process_mode`, is unnamed. Pattern has no driver. Where `run_time` is read from is unspecified (stubbed as `make_run_time_stub`; it needs a named accessor on Run State).
7. `hazard_bound`/`hazard_released` signal shapes are called "proposed/provisional" in Near-Miss, while Obstacle names them as published. The types of `footprint_pieces` in the payload (Array of what) are undefined.
8. Open gates that block shipping content: the hidden-side time budget (`s_ref`, OQ2, OQ15, OQ17) has no oracle, so hidden hazards are banned. The F3 `STEER_ARC` crossover (Pattern OQ1) is unresolved. Real chunk count and pool sizes (Pattern OQ3), padding frequency (OQ11) and all tuning defaults are unmeasured guesses.
9. The test-framework conflict: technical-preferences says GUT, but Obstacle OQ9 says "GUT versus gdUnit4 open" and coding-standards CI lists `tests/gdunit4_runner.gd`. The harness is not settled.
10. Engine facts unverified on 4.7.2 (HIGH): `Script.get_script_method_list()` behavior (Scoring AC-11b), `Resource.duplicate_deep()` (4.5) semantics, `RandomNumberGenerator` seed determinism across Android ARM64 vs desktop (PCG32 is expected to be portable, not verified), and physics-substep behavior. `docs/engine-reference/godot/modules/physics.md` is verified only to 4.6 (Obstacle OQ7).
11. Determinism wording: "bit-identical per `run_id`" holds only for an identical `run_time` sequence at each `hazards_for_segment` call (tier is sampled at window entry, ahead of the ball). Replay needs the same Ball Movement/Run State clock. Pattern's tier-ahead offset is not stated as a number.
12. Platform: the Android 16KB page-size and `FileAccess` note affects Save & Persistence, not these four. Scoring's write-failure path assumes Save returns a status it does not specify to Scoring (`WRITE_FAILED` is handled internally by Save).
13. No numeric per-frame CPU budget is allocated to Obstacle (192-piece worst case), Near-Miss (about 2x per piece) or Pattern, and no memory figure is given (hazard pools are bounded by window recycling only).
14. `juice-feedback.md` and `hud.md` must still carry a `milestone_crossed` row or an explicit decline (Scoring commitment); HUD declined it on 2026-10-01 and Juice's pickup is still marked provisional.
