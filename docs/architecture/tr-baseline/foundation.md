ARCHITECTURE FACTS (Run State)
- Modules: RunStateCore (RefCounted, state machine), RunConfig (config Resource; class name not given), static helper progress_for; a driver/composition-root-owned tick owner; per-system adapters owned by the receiving system (Tube Track adapter, Platform Services adapter, Tilt Input adapter).
- Owns exclusively: phase, run_id, run_time, hit_us, paused_us, resume_us, request queue, the one event-name list. Owns DT_MAX (Open Question 9 resolved: stays here).
- Exposes: tick(world_dt, real_dt)->float dt_eff; request methods (map_ready, start_requested, hit_reported(hazard_id, run_id), pause_requested(source), resume_requested, restart_requested(press_us), menu_requested(press_us)); read of phase/run_id/run_time; the 9 signals above. (Method spellings in tests: request_pause, request_hit; not otherwise specified.)
- Consumes: injected clock, log_sink(level,message), RunConfig plus injected hitstop_actual; requests from loader, Menus, HUD, Obstacle System, Platform Services adapter, Tilt Input adapter.
- Engine classes: none in core. Driver uses Time.get_ticks_usec, _process, process_mode, Input events (InputEventScreenTouch).
- Order: constructed by composition root before subscribers connect; no emission at construction. Per frame: input handlers/adapters send requests, Tilt adapter sensor_lost once per frame before tick, tick(), then owner steps Ball Movement with dt_eff then Tube Track advance(s) if Running.

CONFLICTS OR GAPS (Run State)
- Map loader has no GDD: its name, interface, and whether it sends map_ready or an adapter does is provisional (D9, OQ8).
- Game-loop ADR does not exist: who owns tick(), clock source, and composition root are unwritten (OQ4).
- Request method names are "provisional until sender's GDD exists"; no typed signatures or enum definitions (source enum for pause: button/back/app_interrupted/sensor_lost).
- app_returned request to re-anchor the Paused guard is not defined in RS yet (OQ17); PS AC-16 is blocked on it.
- Which node receives tap-anywhere in Hit is decided (HUD) but press_us handoff API is unspecified.
- RunConfig class/file names not given; hitstop_actual injection path not specified beyond "plain number".
- Collision mechanism/tunnelling at DT_MAX x v_max = 2.5 u and stale-contact physics-frame guard are deferred to a collision ADR (OQ3, OQ17).
- F2 shares not re-measured for new Tube Track defaults; Near-Miss, Environment, Settings handler shares missing; "Score and HUD 2 ms" is one figure for two systems.
- Whether Time.get_ticks_usec stops during device sleep is UNVERIFIED (OQ5); physics interpolation reset on restart teleport UNVERIFIED.
- Wording gap: spec says test plan lives in tests/unit/run_state/test-plan.md (not read; outside the four GDDs).

ARCHITECTURE FACTS (Save & Persistence)
- Modules: PersistMath (static), SaveCore (RefCounted), SaveService (Node, sole real-I/O owner). No Config resource class; knobs are three constants (no *Config).
- Owns exclusively: user://save.cfg file, its temp/corrupt-backup files, [_meta], schema versioning, read validity logic, atomic write path. Does NOT own key semantics or defaults of other sections.
- Exposes: get_value(section,key,default)->Variant; set_value(section,key,value)->bool; persist/flush path invoked on app_backgrounded; (no signals defined).
- Consumes: PlatformServices.app_backgrounded; seams listed above; RateLimitedLog from Platform Services.
- Engine classes (SaveService only): ConfigFile, FileAccess (size check), DirAccess (rename_absolute, remove_absolute, listing), Time (wall clock), signal connection to PlatformServices.

ARCHITECTURE FACTS (Settings & Accessibility)
- Modules: SettingsCore (RefCounted, state-holder), SettingsMath (static: seam_contrast_scale, tilt_sensitivity_validate -> {value, was_corrected}). No Node, no Config resource, no tuning knobs.
- Owns exclusively: current in-memory value of the five settings, the tilt_sensitivity validation, the reduced_motion -> seam_contrast_scale derivation.
- Exposes: set_value(key, new_value)->bool; six getters; signal setting_changed(key: String, new_value: Variant).
- Consumes: Save & Persistence get_value/set_value via seams; Tilt Input SENSITIVITY_MIN/MAX as constructor parameters (reference only).
- Engine classes: none (pure RefCounted/signal).
- Order: constructed by composition root right after SaveService loads and before Menus, Platform Services consumers, Tilt Input, Tube Track and Environment read getters; no per-tick participation.

CONFLICTS OR GAPS (Settings & Accessibility)
- CR6 says "six read-only getters" but the description lists five plus a sixth; count is consistent only counting get_seam_contrast_scale (6 total); AC-15 mentions "the six named methods".
- Platform Services' intensity setter is not defined, and PlatformServices constructor order vs SettingsCore (PS needs initial haptics_enabled/intensity, Settings needs Save; PS must exist for Save's signal) is unspecified: pick order Platform node, Save, Settings, then push initial values.
- setting_changed payload is Variant; no typed per-setting signals; Tube Track "every frame or on setting_changed" leaves the consumer to choose.
- Type coercion: stored int 1 vs float default 1.0 for tilt_sensitivity depends on Save's TYPE_MISMATCH rule (typeof(default) unspecified).
- Status is "Designed, pending independent /design-review"; consumer wiring (AC-19/20) has no owner or date.
- Settings screen UX is unspecified (OQ2); text scaling / extra accessibility deferred post-MVP (OQ5).
